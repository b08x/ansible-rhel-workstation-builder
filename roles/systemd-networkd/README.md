# Ansible Role: systemd-networkd

A comprehensive Ansible role for configuring **systemd-networkd** and **systemd-resolved** on RedHat family systems (Fedora, Rocky Linux, RHEL). This role manages network interfaces, virtual network devices, and link-layer configurations while facilitating the transition from NetworkManager.

## Features

- ✅ **Network Configuration**: Declarative management of `.network` files.
- ✅ **Virtual Devices**: Support for Bridges, Bonds, VLANs via `.netdev` files.
- ✅ **Link Overrides**: Custom `.link` file generation for hardware-level settings (MAC, MTU).
- ✅ **Resolved Support**: Full configuration of `systemd-resolved`.
- ✅ **Service Transition**: Automated switching from NetworkManager to systemd-networkd.
- ✅ **Cleanup**: Optional removal of unmanaged configuration files.

## Requirements

## Role Variables

All variables are defined in `defaults/main.yml`.

### Global Configuration

| Variable | Default | Description |
|----------|---------|-------------|
| `systemd_run_networkd` | `true` | Enable and start systemd-networkd service. |
| `systemd_interface_cleanup` | `false` | Remove unmanaged network/netdev files with the defined prefix. |
| `systemd_networkd_prefix` | `"general"` | Prefix for files generated by this role. |
| `systemd_networkd_update_initramfs` | `"dracut -f"` | Command to update initramfs after link changes. |

### Network Interfaces

Defined via `systemd_networks` list.

```yaml
systemd_networks:
  - interface: "eth0"
    address: "dhcp"
    usedns: true
  - interface: "br0"
    address: "192.168.1.10/24"
    gateway: "192.168.1.1"
    mtu: 1500
    ipforward: true
```

**Common parameters:**
- `interface`: Name of the interface to match.
- `address`: IP address (CIDR notation) or `"dhcp"`.
- `gateway`: Default gateway IP.
- `mtu`: Interface MTU size.
- `usedns`: Use DNS from DHCP (boolean).
- `bridge`/`bond`/`vlan`: Bind interface to a virtual device.
- `static_routes`: List of static routes.
- `routing_rules`: List of routing policy rules.

### Virtual Network Devices (NetDevs)

Defined via `systemd_netdevs` list.

```yaml
systemd_netdevs:
  - NetDev:
      Name: "br0"
      Kind: "bridge"
```

### Systemd-resolved

| Variable | Default | Description |
|----------|---------|-------------|
| `systemd_resolved` | `{}` | Key-value pairs for `resolved.conf`. |
| `systemd_resolved_available` | `true` | Enable systemd-resolved management. |

Example:
```yaml
systemd_resolved:
  DNS: "8.8.8.8 1.1.1.1"
  FallbackDNS: "9.9.9.9"
  DNSOverTLS: "yes"
```

## Dependencies

Requires `ansible.posix` for sysctl configuration if `ipforward` is used.

## Example Playbook

### Basic DHCP Setup

```yaml
- hosts: workstation
  become: true
  roles:
    - role: systemd-networkd
      vars:
        systemd_networks:
          - interface: "enp*"
            address: "dhcp"
```

### Bridge with Static IP

```yaml
- hosts: server
  become: true
  roles:
    - role: systemd-networkd
      vars:
        systemd_netdevs:
          - NetDev:
              Name: "br0"
              Kind: "bridge"
        systemd_networks:
          - interface: "enp3s0"
            bridge: "br0"
          - interface: "br0"
            address: "10.0.0.5/24"
            gateway: "10.0.0.1"
```

## Transitioning from NetworkManager

This role handles the transition by:
1. Installing `systemd-networkd` packages.
2. Deploying configurations to `/etc/systemd/network/`.
3. Starting `systemd-networkd`.
4. Stopping and disabling `NetworkManager`.

**Warning**: Ensure your configuration is correct before running, as network connectivity may be briefly interrupted during the transition.
